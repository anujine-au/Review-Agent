# Audit Report Reviewer Agent

ББСБ-ын Дотоод аудитын газрын салбарын аудитын тайланг **Reporting** шатанд дээд шатны хянагчийн байр сууринаас хянах Claude Code агент.

│   ├── system_prompt.md          # Sections 0–36, 43–46

## Вэб хэрэглүүр (санал болгох арга)

Шаардлага: Node.js 18+ (энэ компьютерт v24 LTS `AppData\Local\Programs\nodejs`-д суусан). `npm install` шаардлагагүй — гадны сан ашиглаагүй.

1. `start-server.cmd` дээр давхар дарна. Цонхонд **нэвтрэх код** харагдана (`web/access_code.txt`-д хадгалагдана).
2. Хөтөч дээр `http://localhost:8080` нээгээд кодоо оруулна.
3. Аудитын мэдээллээ бөглөж, Word тайлан, Excel хавсралт, нотолгоогоо чирж оруулаад **Review эхлүүлэх** дарна.
4. Явц нь шууд харагдана. Дуусахад шийдвэр, оноо, Critical/Major/Minor тоо, бүтэн review тайлан тэр хуудсан дээр гарна. **⬇ Татах** цэснээс PDF, Word (.docx), Excel (.xlsx), HTML, бүгдийг нэг ZIP, эсвэл эх `.md` / `.json` файлаар татаж авна (PDF-ийг Microsoft Edge / Chrome-оор үүсгэнэ). Review дууссаны дараа ишлэл бүрийг тайлангийн эх бичвэртэй автоматаар тулгана (`server/verify.js`): таараагүйг агентаар нэг удаа засуулж, олдоогүй ишлэлийг ⚠ тэмдгээр харуулна.

**Дотоод сүлжээнд нээх:** IT-аас Windows Firewall дээр port **8443** (TCP, inbound)-ийг нээлгэсний дараа `start-server.cmd --lan` гэж ажиллуулна. Сүлжээнд зөвхөн **HTTPS**-ээр ажиллана: `https://<энэ компьютерийн IP>:8443`. Өөрөө гарын үсэг зурсан сертификат тул хөтөч анхааруулга гаргана. Серверийн цонхонд харагдах SHA256 fingerprint-тэй тулгаж баталгаажуулна. Сервер ажиллаж байх хугацаанд энэ компьютер асаалттай байх ёстой.

## Claude Docs-оор хамтран засах (масктай)

1. Review дууссаны дараа **⬇ Татах → ☁ Claude Docs руу бэлтгэх** дарна. `server/docs_prep.js` нь token-той үр дүнг дахин далдалж (РД, имэйл, утас, данс, нөхцөл залгавартай нэр), 1,000+ жинхэнэ утгатай тулгана. Нэг ч үлдвэл илгээхийг хориглоно.
2. Хуулагдсан `/publish-docs <jobId>` командыг Claude Code-д бичнэ → зөвшөөрөл асууна → Doc үүснэ (тэмдэглэл бүр «Аудиторын хариу» + **Төлөв** dropdown-той).
3. Doc-ийн **Share**-ээр эрх өгнө: аудитор — Edit, хянагч — Edit, удирдлага — View (зөвхөн байгууллагын хүрээнд).
4. Аудитор хариу бичиж, Төлөвийг «Аудитор засварласан» болгоно, эсвэл мөрөнд comment бичээд Claude руу илгээнэ.
5. Хянагч `/sync-docs <jobId>` → Claude өөрчлөлтийг уншиж, мөр бүрт «Хангалттай / Хэсэгчлэн / Хангалтгүй» comment бичнэ. «Хянагч баталгаажуулсан» Төлөвийг зөвхөн хүн тавина.

Doc claude.ai дээр хадгалагдах тул илгээхээс өмнө ДАГ-ын мэдээллийн аюулгүй байдлын журмаар зөвшөөрөгдсөн эсэхийг баталгаажуулна. Job 7 хоногийн дараа устахад `docs/state.json` (Doc-ийн холбоос) хамт устна, Doc өөрөө үлдэнэ.

## Аюулгүй байдал

| Давхарга | Хамгаалалт |
|---|---|
| Хувийн мэдээлэл | Claude-д илгээхээс өмнө нэр, РД, утас, имэйл, хаяг, дансыг `[PERSON-0001]` зэрэг token-оор солино (анхдагчаар асаалттай). Нэг утга = нэг token тул тулгалт хэвээр. Том жижиг үсэг ялгахгүй (ЗОРИГОО = Зоригоо), нөхцөл залгасан хэлбэрийг (Зоригоогийн, Бат-Эрдэнийн) таньж, мөнгөн дүнг хөндөхгүй. Маскийн дараа жинхэнэ утга үлдсэн эсэхийг дахин шалгаж, үлдвэл review-г зогсооно (Claude-д юу ч илгээхгүй). Token → жинхэнэ утгын түлхүүр (`mask_map.json`) Claude-ийн хандах боломжгүй газар хадгалагдаж, үр дүнг танд харуулахдаа л буцааж тавина. |
| Зураг | Screenshot-ийг анхдагчаар Claude-д илгээхгүй (зурган дээрх мэдээллийг далдлах боломжгүй). Хэрэглэгч тусгайлан зөвшөөрвөл л илгээнэ. |
| Claude-ийн эрх | Зөвхөн `Read, Glob, Grep, Write, Edit`. Shell, интернэт, MCP, sub-agent байхгүй. Зөвхөн `jobs\<id>\sandbox\`-ийг уншиж, `sandbox\output\`-д бичнэ. Эх файл, түлхүүр, бусад review-д хандахгүй. Review-ийн бичлэг (transcript) хадгалагдахгүй. |
| Диск | `jobs\`, `logs\`, нэвтрэх кодын файл Windows EFS-ээр шифрлэгдсэн. |
| Хадгалах хугацаа | Задалсан текст review дуусмагц устна. Оруулсан эх файлууд хувилбар (C1, C2…) бүрээр `jobs\<id>\originals\`-д хадгалагдаж, «Эх файлууд» табаас татагдана (татах бүр логт). Review бүхэлдээ 90 хоногийн дараа автоматаар устна (`--retention-days`); эцэслэн батлагдсан тайлан, эх файлууд `archive\`-д 10 жил. |
| Нэвтрэлт | Хэрэглэгч бүр өөрийн нэр, нууц үгээр (scrypt hash, 10+ тэмдэгт). Role: **Admin** (хэрэглэгч удирдах), **Хянагч** (бүх review, устгах, Docs), **Аудитор** (зөвхөн өөрийн review), **Удирдлага** (харах, татах). Admin шинэ хэрэглэгчид түр нууц үг өгч, эхний нэвтрэлтэд солиулна. Үйлдэл бүр хэрэглэгчийн нэрээр `logs/`-д бүртгэгдэнэ. 20 тэмдэгттэй код нь зөвхөн анхны admin-ыг үүсгэхэд. Нууц үг мартвал серверийн компьютер дээр `node server/users.js reset <нэр>`. 30 мин идэвхгүй → гарна, 5 буруу оролдлого → 15 мин түгжинэ. |
| Вэб | Анхдагчаар зөвхөн localhost. Host header шалгалт, cross-origin хаалт, CSP, X-Frame-Options, файлын агуулгыг өргөтгөлтэй нь тулгах. |
| Бүртгэл | `logs\access-YYYYMM.log` — нэвтрэлт, review үүсгэх/эхлүүлэх/татах/устгах (файлын нэр, агуулгагүй). |

**Техникээр шийдэх боломжгүй үлдэгдэл эрсдэл:**

- Далдлагдсан текст Anthropic-ийн серверт боловсруулагдана. Байгууллагын мэдээллийн аюулгүй байдлын бодлогоор зөвшөөрөгдсөн эсэх, Claude бүртгэлийн өгөгдлийн нөхцөлийг IT/Compliance-аас баталгаажуулна.
- Word-ын чөлөөт текст дэх бүтэн нэрийг (Excel-д байхгүй, “Б.Болд” хэлбэрээс өөр) автоматаар бүрэн илрүүлэх боломжгүй.
- Энэ компьютерийн администратор эсвэл таны Windows бүртгэлд нэвтэрсэн хүн өгөгдөлд хандаж чадна.
- Review нь энэ компьютерт нэвтэрсэн Claude бүртгэлийн эрхээр ажиллаж, түүний хэрэглээнд тооцогдоно.

Excel-ийн тооцоолол (мөрийн тоо, нийлбэр, давхардал, ангиллаар бүлэглэсэн дүн)-ыг `server/extract.js` урьдчилан хийж `*.profile.txt` болгоно. Profile-д хамрагдаагүй нарийн тооцоог агент “Unable to validate” гэж тэмдэглэж, аудитороос нэмэлт тооцоо шаардана. Нэг удаад нэг review ажиллана, бусад нь дараалалд орно.

## Claude Code-оор шууд ашиглах

1. Тайланг `input/report/`, Excel-ийг `input/excel/`, журам болон бусад нотолгоог `input/evidence/`-д хуул.
   - `.doc` / `.xls` бол Word / Excel-ээр `.docx` / `.xlsx` болгож хадгална.
2. VS Code терминал дээр энэ хавтаст `claude` ажиллуул.
3. Командыг өг:

   ```
   /review-audit Audit: Зээлийн процессын аудит, Code: IA-2026-014, Branch: Дархан салбар
   ```

   Эсвэл `prompts/user_prompt_template.md`-ийг бөглөөд чатад хуулж болно.
4. Үр дүн `output/` хавтаст гарна.

## Шинэ аудит эхлэхийн өмнө

`input/*/`, `work/extracted/`, `output/` доторх өмнөх аудитын файлуудыг устгах эсвэл архивлана. Өөр аудитын файл холилдвол review буруу гарна.

## Анхаар

Агентын шийдвэр нь **Reviewer decision support** юм. Эцсийн батлах эрх хүнд.

## Ажлын урсгал (2026-10-12)

`DRAFT → SUBMITTED → CAE_REVIEW → RETURNED → RESUBMITTED → … → APPROVED_FINAL` (аль ч үед `CANCELLED`). Төлөв root job-ийн `job.json.workflow`-д; хувилбар v{n} = C{n}.

| Хэн | Юу хийнэ |
|---|---|
| Аудитор / ахлах аудитор (баг) | Тайлан + хөтөлбөр оруулж «Хянуулах»; захирал буцаасны дараа «Засвар оруулах» («юу зассан» заавал). AI-ийн санал, дүгнэлт, тоог **release хүртэл огт харахгүй** — зөвхөн царцсан `feedback_v{n}` |
| ДАГ-ын захирал (cae) | Санал шийдвэрлэх → «Батлаад илгээх» (feedback царцана, багт мэдэгдэл) → эцэслэн батлах → «Эцсийн тайлан» (.docx / PDF / бүх хувилбар ZIP) |

- Харагдах байдлыг сервер нэг газар хаадаг (`server/workflow.js` `seesInternals`, `restrictJob`); бэлтгэгч ≠ хянагч (DOC-1917 §9) — багийн гишүүн шийдвэр, release, finalize хийвэл 409.
- Мэдэгдэл: header-ийн 🔔 (`logs/notifications.jsonl`); имэйл — `web/smtp.example.json`-ийг `web/smtp.json` болгож бөглөнө.
- Эх файл хувилбар бүрээр `jobs/<id>/originals/` (sha256, линк бол url + татсан огноо); идэвхтэй урсгалтай гинж автомат устгалд орохгүй.
- Шалгуурын тест: `node --test tests/workflow.test.js` (түр хавтсанд тусдаа сервер, Claude дуудахгүй).
- **Нэвтрэлтийг асаах шаардлагатай** (`node server/users.js login on`) — эс бөгөөс role-ийг хэрэглэгч өөрөө сонгох тул §5 хамгаалалт ажиллахгүй.
